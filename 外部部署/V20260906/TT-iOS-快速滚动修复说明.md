# TT iOS 快速滑入状态栏：修复与回归（2026-09-07）

## 适用版本与范围

新材质分支只在 **TT + iOS/iPadOS + native-flow** 三个条件同时成立时启用。
原生 SillyTavern iOS、Android 酒馆与 TT Android 保留原渲染分支及性能偏好行为。

## 代码层面的原因

1. 旧 TT 性能识别读取 HUD iframe 的 `?host=tauritavern-mobile`；流内嵌入是在酒馆助手 srcdoc 内直接载入模块，不带此参数。
2. native-flow 的默认 low 只减去部分材质；SVG bloom、卡片滤镜、混合模式，以及按整张弹性画布尺寸创建再裁剪的 `.pg` 层仍在。保存过 auto 偏好的用户还会恢复更多效果。
3. 阅读区开始的快速滚动发生在宿主，HUD 内的 touch 回调未必触发，因此依赖“触摸时隐藏、结束再恢复”的处理不覆盖这个入口。

以上是代码与浏览器夹具确认的渲染风险，符合所述分块变黑现象。当前没有 iOS TT 真机 GPU 进程退出日志；设备上的直接崩溃原因仍待真机核验。

## 修复方式

- 壳层在导入 HUD 前传递宿主标记；旧粘贴壳通过同源祖先的 TT 标记补充识别。仅 iPhone UA 不作为 TT 依据。
- TT iOS 使用稳定的低负载材质；用户保存的 auto/low 偏好不被改写，其它宿主照常生效。
- 竖屏面板使用相同轮廓的 SVG 直接填色和分段彩色描边，省去整画布裁剪层和 bloom 定义。
- 该分支下关闭 filter、backdrop-filter、混合模式及主动图层提示；保留缩放、卡片局部遮罩、普通阴影、图片、文字、尺寸和点击区域。
- 不监听快速滑动来隐藏内容，也不反复切换材质。
- 壳层“已绘制”判据从装饰节点数量调整为可见内容面板，避免简化 SVG 后恢复短页面时被误判成空壳。

### 实现与维护

- `scripts/build-ios-tt-direct.mjs`：校验普通 0906 壳后，以单文件 IIFE 构建 HUD，内嵌 CSS；严格检查替换锚点，避免壳层变动后静默打包错误。
- 构建编号由源码、普通壳、构建脚本、依赖锁及素材根地址共同生成；设置页的 HUD 编号与顶部版本行应一致。
- 内嵌入口不写入宿主共享的 `manager.nativeEntry`，也不使用临时 Blob URL，避免跨楼层复用失效地址或重试查询串问题。
- 内嵌 IIFE 现以普通脚本同步执行，外部 ESM 入口仍使用 module。启动期脚本异常会使挂载失败；随后再按真实内容就绪确认加载完成。早期测试曾检出等待 inline module 的 `load` 事件导致提示一直停留的缺陷，楼层重建也有覆盖。
- 该文件是自动生成产物；后续源码变化后重新运行生成命令，避免直测文件本身过期。

### 直测启动修正

- 原版本提示条在 `resolveNativeEntry` 才创建，主脚本提前退出或未执行时，本来就没有提示。
- 现在先放入静态的浅黄色 `0906 启动检查`，再用独立短脚本记录 `probe / shell / frame-missing / native-flow / mount / entry / bundle / first-content`。主脚本的语法错误不会一并破坏这个前置脚本。
- 等待超过 12 秒显示 `timeout`，执行异常显示 `script-error`。仅记录异常类别、行列号和宿主识别布尔值，不复制异常消息、聊天内容、URL 或令牌，不上传诊断信息。
- 静态提示绝对定位在状态栏文档内，不参加 `body.scrollHeight`，避免在启动中断时与酒馆助手自动量高形成不断增高的反馈。
- 自包含 IIFE 以普通脚本同步执行，不再借用 module 的调度和 load 行为；捕获同步执行时派发到 window 的异常，避免部分 DOM 存在时把失败的挂载误判为成功。这是已验证的启动边界修正，不是已证实的真机黑屏根因。
- 启动成功后收起黄色提示；TT iOS 保留带 `tt-ios-0906-f08de5888f` 的正常版本行。
