## 2. 已经完成的部分

- 纯 JS 引擎与页面分离；种子随机可复现，适合做规则回归。
- 每场 3 箱，每箱最多 5 轮；玩家加 4 位 NPC，共 5 位参与者。
- 7×6 仓库；目标生成数量 4–9 件；不同品类、品质、品相、赝品和矩形占格。
- 公共账本与私有账本；10 种仪器，4 个装备位。
- 6 种 NPC 人格；按估值、利润目标、进取心、偏好等参数决定行为。
- 当前成交价为全局历史最高价；结算包含佣金、钻验花费、真值、净收益及 S–F 评级。
- 共享钱包接入、随钱包量级缩放、4 套视觉主题、窄屏布局、逐件开箱、三箱总账。

这些说明项目已是可玩的原型，不是只有空页面。仍应区分“流程走通”和“暗拍规则正确”。

### 3.2 三个可复现的规则问题

详见 `engine-audit.json`，复现脚本 `tools/audit-engine.mjs`。测试使用高预算以隔离资金限制，这不是真实玩家经济指标。

**A. “估价下限”的说法与计算不同**

- 配置：`seed=1`，预算 `1e9`，装备 `scope-s + scope-m`。
- 第 2 回合估价 **79,492**，整箱真值 **59,519**。
- `knownEstimate()` 使用品质均值、品相均值、赝品期望，以及价值区间中点；所以它可能高于真实值，也不保证单调上升。
- 建议：要么改标签为“参考估值”，要么实现真正的候选集合最小值；若显示区间，分别命名保底、期望、上限。

**B. 暗拍存在同轮信息泄漏**

- `bid()` 先写入玩家 `playerBest`，之后才循环 NPC；`rivalBid()` 会读取 `visibleHigh(state)`。
- NPC 报价又立即更新各自 `best`，后面的 NPC 可受同轮前面 NPC 影响。
- 同样 `seed=1`：玩家首轮出 5,630 时四位 NPC 均出价；出 10,000,000 时四位 NPC 当轮全部退出。配合代码顺序说明它们使用了尚未全员公开的当轮信息。
- “加密出价器”只是特殊隐藏玩家报价，并没有把所有参与者都变成统一的同步暗拍。
- 建议：从回合开始快照生成各自决策，全部提交后统一揭示与评标。历史报价可以公开；本轮未揭示报价不进入其他人的决策上下文。

**C. “放弃本箱”仍可能以旧价获胜**

- `seed=1` 首轮出 10,000,000，之后调用 `bid(null)`。
- 实测 `playerActive=false`，但最终 `won=true`，成交价仍为 10,000,000。
- 原因：放弃只停止出价，`hammer()` 仍遍历历史最高价。
- 这不应不加区分地定义为 bug：若报价具有约束力，保留旧价可能合理；问题是界面用语与合同语义尚未明确。
- 建议：明确选择“停止加价但原报价仍有效”还是“本轮/本箱退出”，再统一按钮、超时、NPC 退出和结算处理。

### 3.3 另两项代码层风险

- **同价偏向玩家**：`hammer()` 初始 winner 是玩家，只在 NPC 严格更高时替换；并列最高价默认由玩家拿走，未见公开说明或加赛。
- **早报价未必早成交**：玩家仍 active 时，即便其他人全部退出也可能继续等回合；现有“每轮密封出价”的外观与历史最高价累计规则混合。若采用《异环》的回合价差终止，需要重新定义评标，而不是只把 5 改成 6。

## 5. 推荐实施顺序（尚未执行）

### P0 · 规则语义与入口

1. 先确定“近似《异环》的暗拍”或“现有历史累积竞价”作为主模式；给规则策略起明确名字。
2. 重做同步提交/公开，隔离当前轮报价，明确平价和弃权。
3. 处理估价标签与计算的一致性。
4. 加入大厅 `GAMES` 配置，并复核钱包、iframe 事件和游戏状态 key。
5. 新增无 DOM 规则回归：同 seed 同动作同结果、NPC 独立于玩家未公开报价、恰好倍率/超过倍率、R5/R6 同价、弃权、预算、费用、只结算一次。

**验收**：原有四尺寸流程及大厅检查通过；关键规则有种子可复现测试；游戏说明与代码一致。

### P1 · 核心信息博弈

- 新增藏品目录与候选筛选，区分真实物品数据与玩家可知视图。
- 新增一个独立帮手槽，先制作 3 种原创信息风格。
- 若采用回合价差机制，顶部常驻成交门槛，配合投标/揭示动画。
- 降低情报段落噪音，突出本轮新增、公开/私有归属和对应格子。
- 避免“所有 NPC 直接按真值强相关估价”成为玩家永远吃亏的来源；现有模型已用真值弱相关信号，未来可逐步转为 NPC 独立信息账本。

**验收**：玩家能解释一次出价依据；不靠整箱先验提示也能通过候选排查做决策。

### P2 · 开箱与收藏循环

- 在现有逐件翻开上增加累计价值、品质音效/动效和最终揭晓节奏。
- 结算拆明成本，新增出售与留藏；优先加入图鉴首次发现记录。
- 保存与恢复中途状态，防止刷新时重复结算；需要版本化迁移策略。

**验收**：赢拍、亏损、流拍、主动退出都产生清楚的结算；收藏持久化可测。

### P3 · 深度与经济

- 会场门槛、场地事件、进阶 NPC、赛季统计。
- 复用现有模拟工具重新测盈利分布、空手策略、各装备策略；旧设计稿中的 ROI 只作为历史记录，不当本版验收结果。
- 多人网络对战、交易行、3D 收藏馆暂不列首版必需项；浏览器单机 NPC 先验证是否好玩。

## 6. UI 以外的待办

- 时间语义：暂停、切后台、断线与超时，现有 30 秒强退出是否符合预期。
- 资金语义：钻验费用、门票、佣金、成交金额和收益何时入账；避免 UI 钱包与 session 预算不一致。
- 数据权限：前端单机可调试读取真值很正常，但 UI 和 NPC 决策应各自只读明确的视图。
- 宿主场景：当前截图是直接打开页面，不替代酒馆嵌入、强制横屏、软键盘和真机触控回归。

推荐下一步直接做 **P0 规则语义确认与测试**，再补 **P1 图鉴/帮手**。当前布局已足够支撑玩法验证，先不投入大规模装饰美术。
