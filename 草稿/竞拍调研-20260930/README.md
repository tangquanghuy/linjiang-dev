## 最重要的结论

1. **方向是“根据有限情报估值的暗拍”，不是简单加价按钮游戏。** 两个参考都将信息差、角色能力和揭晓藏品作为核心。本项目已有相近基础。[S03/S05；NTE 852/858/862；BK 02]
2. **现有三栏布局其实已经接近参考。** 左侧竞拍人，中间回合/情报，右侧仓库，底部操作；优先补齐规则语义、图鉴推理及结束后的收藏循环，而不是先推倒 UI。[截图实看；项目页面]
3. **项目的“密封出价”与实际执行顺序有偏差。** NPC 在玩家当轮出价落入状态后再决策；同轮 NPC 也顺序观察前面的最高价。应在重做暗拍前优先处理。[引擎 `bid/rivalBid/visibleHigh`；`engine-audit.json`]
4. **项目“当前估价”并非严格价值下限。** 已复现估价 79,492 大于整箱真值 59,519；旧设计稿和注释应与实现区分。[`knownEstimate`；`engine-audit.json`]
5. **独立页面可完整游玩，大厅入口尚缺。** 四个尺寸的三箱流程走通；现有测试最后在大厅标签和 `#auction` 路由处失败。[`project-smoke.log`]

## 复现

在仓库根目录运行（现有 Node/Playwright；图片工具额外使用本机已安装的 Pillow）：

```powershell
# 原有检查：预计独立页面流程通过，大厅检查失败
node scripts/check-auction.mjs --shots

# 调研专用：复用现有流程，截图前等待动画稳定，并保存日志
node "草稿/竞拍调研-20260930/tools/capture-project.mjs"

# 可复现的只读规则诊断
node "草稿/竞拍调研-20260930/tools/audit-engine.mjs"

# 重新抓取原图 → 如有网络失败则重试 → 重建清单/图库
python "草稿/竞拍调研-20260930/tools/fetch-images.py"
python "草稿/竞拍调研-20260930/tools/retry-images.py"
python "草稿/竞拍调研-20260930/tools/build-gallery.py"
```

`gallery.html` 可直接用浏览器打开，运行时不依赖外部 CDN。工具执行只写本调研目录或原有测试的 `artifacts/auction/`。没有提交 Git，也没有触碰工作区原先已有的部署文件改动。
